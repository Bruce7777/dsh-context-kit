## 价格与账目限制

采用2026-11-09核对的[DeepSeek官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，模型为 `deepseek-flash`。每百万 token 的谷时价格：缓存读取0.02元、未缓存输入1元、输出4元；峰时均为两倍。逐调用依据已记录的接纳时间分配时段，缺接纳标记才用对应 step/compaction 的开始时间；11月9日按普通周一处理。对跨18:00的调用保留开始/结束时段两种估值边界，官方页面没有明确跨界结算细节。所有价格计算均为实际 usage 乘公开单价的估算，不能称账户实扣账单。

费用公式为 `未缓存输入×对应单价 + 缓存读取×对应单价 + 输出×对应单价`，最后除以一百万。提供商计入的推理已经在输出中，不重复加收。缓存写入 usage 均为0；缺失字段不能推算为0。

第53轮双方发生传输失败和自动重试；候选原 turn 最终以 TRANSPORT 错误结束，对照原 turn 最终完成。失败尝试没有返回 provider usage，费用未知。主控保留原始记录和候选已收到的六次成功生成用量，在原候选 Session 用同一任务消息恢复；对照不重发。**前52轮的完整核算不受影响；第53轮之后只能报告收到 usage 的已知费用，不能承诺全程没有漏计。** 恢复期间未重启实例、清空历史或重建测试 Session。

主控随后查询系统电源日志，确认第53轮期间19:09:39进入睡眠，20:19:00唤醒，日志睡眠间隔4161秒。该轮墙钟耗时包含宿主睡眠，不能据此评价插件性能；这不等于已确定每次传输失败的唯一原因。部分失败流已有输出但缺usage，不能仅因最后一次重试没有内容而按零收费。完整费用审计固定保留睡眠和未知费用之前的52轮；后续数据另列。

## 缓存与实现

两边 DSH 0.2.2-rc.1、Node 24.15.0、`deepseek-official/deepseek-flash/max`，主输出上限256000。专用单作者 preset 只有 persona 与文件工具，不挂载自己的 Basic 压缩组；3080 只有根 Budgeted 自动提供者，3082 只有根 Basic。两边 pruner 关闭，对照临时关闭 supervisor。候选使用默认131072上下文预算、24576近期保留、4096摘要正文目标、16384摘要输出上限，主动裁剪关闭。没有降低预算、手动 compact、注入无关文本或委派作者。

首次成功摘要在第6轮策划阶段，前52轮已覆盖其后46个完整创作/审改轮。原生在此截止点没有摘要。摘要本身缓存命中约99.4%；真实历史替换后的首次主请求需要冷填充，后续恢复高命中。插件不改主请求顺序与序列化，召回 schema 在安装后稳定；缓存由提供商控制，这些观察不等于对所有运行保证缓存命中。

全部输入的缓存读取占比为候选98.52%、原生99.85%；候选未缓存输入高200.81%、输出高38.35%。总输入主要减少的是便宜的缓存读取，不能用输入降幅直接推算账单。8次摘要后的首次主请求未缓存输入约45,386—55,644 token，均已计入；[摘要前后各三次主请求数据](../benchmarks/novel/results/summary-cache-through052.json)支持分别观察摘要命中与替换后的冷填充，不将所有未缓存输入都归因于压缩。

最初两条策划消息限制为文件读写，第3轮起两边同样澄清为允许本地文件及当前 Session 查询（如有），仍禁外网和其他作者。更正发生在首次摘要之前，保留原消息与全部成本。对照因权限设置另有107字符系统来源用户消息；测试任务、模型、persona、公共工具相同，但候选有两个额外 recall schemas，不声称完整请求逐字相同。

## 文学质量口径

首要目标是可读性、人物关系、情节场景、自然对白和文笔。吸引力25%、因果与节奏20%、人物关系25%、对白15%、文笔15%；明显穿帮只作有前后原文证据的附项，不设姓名记忆问答。匿名甲乙由两份互不通信的AI评读分别按AB/BA顺序阅读，不能称真人实验或统计意义上的质量非劣效证明。若排序翻转，或两次分差都小于5分，不宣布明确胜者。

第20轮前8章的探索性评读：两份AI报告分别给候选/原生80.5/83.5和83/76.5，排序翻转。只能判断该阶段接近且对评读顺序敏感，不能推出后续章节或全书质量。评读意见没有发送给作者。正式终点评读与全程结果另列于后续归档；前48章仍是阶段稿，不要求全书完结。
